Rationale

Why Do We Need This Architecture?

Understanding the risks vs. benefits of proper VPC architecture.

🚨 Without Proper Network Design

  • Servers become publicly exposed
  • Security risks increase dramatically
  • No separation between frontend & backend
  • Hard to scale the infrastructure

✅ With This Architecture

  • Public servers are accessible to users
  • Private servers are fully protected
  • Internet access is controlled via NAT
  • Architecture is scalable & HA-ready

Implementation

Step-by-Step Setup Guide

Complete hands-on tutorial to build this architecture from scratch.

1

Create the VPC

AWS Console → VPC → Create VPC
  • Name: My-VPC
  • IPv4 CIDR: 10.0.0.0/16
  • Tenancy: Default

Click Create VPC.

2

Create 4 Subnets

VPC → Subnets → Create Subnet → Select My-VPC
SubnetCIDRAZPublic IP
Public-Subnet-110.0.1.0/24ap-south-1a✅ Enabled
Public-Subnet-210.0.2.0/24ap-south-1b✅ Enabled
Private-Subnet-110.0.3.0/24ap-south-1a❌ Disabled
Private-Subnet-210.0.4.0/24ap-south-1b❌ Disabled
⚠️ Important: Enable Auto-assign Public IPv4 only for public subnets.
3

Create Internet Gateway

VPC → Internet Gateways → Create
  • Name: My-IGW

After creation: Attach to VPC → My-VPC

ℹ️ Public subnets can now connect to the internet after route table config.
4

Configure Public Route Table

VPC → Route Tables → Create
  • Name: Public-Route-Table
  • VPC: My-VPC

Add Route: 0.0.0.0/0 → Internet Gateway

Associate: Public-Subnet-1 & Public-Subnet-2

5

Create NAT Gateway

VPC → NAT Gateways → Create
⚠️ NAT Gateway must be in a PUBLIC subnet.
  • Name: My-NAT
  • Subnet: Public-Subnet-1
  • Connectivity: Public
  • Allocate Elastic IP
6

Configure Private Route Table

VPC → Route Tables → Create
  • Name: Private-Route-Table
  • VPC: My-VPC

Add Route: 0.0.0.0/0 → NAT Gateway

Associate: Private-Subnet-1 & Private-Subnet-2

ℹ️ Private instances can now access internet securely via NAT.
7

Create Security Groups

VPC → Security Groups → Create

Create 2 Security Groups (see Security section below).

8

Launch EC2 Instances

EC2 → Launch Instance

Instance-2Public-Subnet-2✅Public-Instance-SG

Traffic Flow Patterns

How traffic traverses the architecture.

Public — Inbound

  • 👤
    User initiates request
  • 🌐
    Traverses Internet
  • 🚪
    Enters My-IGW
  • 🖥️
    Reaches Public EC2

Private — Outbound

  • 🖥️
    Private EC2 sends request
  • 📋
    Private-Route-Table
  • 🔀
    My-NAT (Public Subnet)
  • 🚪
    Exits via My-IGW
  • 🌐
    Reaches Internet

Public: Instance → Route Table → IGW → Internet
Private: Instance → Private RT → NAT → IGW → Internet
Testing

Connectivity Verification

Validate architecture using bastion host pattern.

1

SSH into Public EC2 (Bastion)

ssh -i key.pem ubuntu@<Public-IP>
2

Verify internet on Bastion

ping google.com
ℹ️ Connected via Internet Gateway.
3

Transfer SSH key & set permissions

chmod 400 key.pem
4

SSH from Bastion to Private EC2

ssh -i key.pem ubuntu@<Private-IP>
Why can't we SSH directly?
Private instances have no public IPs — only private IPs accessible within the VPC. The Bastion Host acts as a jump server.
5

Verify outbound from Private EC2

ping google.com
How does this work?
Private EC2 → Route Table → NAT Gateway → IGW → Internet → response returns same path.
✅ Outbound internet access works
❌ No direct inbound internet access
✅ Internet via NAT, not direct IGW
